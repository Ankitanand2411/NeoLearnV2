# NeoLearn — Socratic AI Adaptive Learning Engine

A production-grade educational platform that transforms passive study into an interactive, character-driven dialogue with historical mentors. NeoLearn combines **historical mentor personas**, **Retrieval-Augmented Generation (RAG)**, **LangChain orchestration**, **LLM-as-Judge evaluation**, and **Item Response Theory (Rasch/1PL with a Bayesian ability update)** adaptive quizzing to guide students toward genuine understanding.

### End-to-End System Explanation

NeoLearn is not just a chatbot; it is a **task-oriented Multi-Agent pipeline** designed for educational pedagogy. The system leverages three distinct AI roles, a structured RAG pipeline, and Item Response Theory (IRT) to adapt to the user.

**1. The Socratic Tutor Agent (Front-Line)**
When a user selects a topic (e.g., "Special Relativity" with Albert Einstein), the frontend connects to the backend via Server-Sent Events (SSE). 
*   **Structured RAG:** The backend performs a deterministic SQL query to Supabase to fetch the highly curated curriculum (`explanation` and `key_takeaway`). 
*   **Prompt Fusion:** It fuses this RAG context with the chosen Historical Persona (Einstein's voice) and the user's current Mastery Level. 
*   **Action:** The LLM streams Socratic responses, refusing to give direct answers and instead forcing the user to use active recall via the Feynman Technique.

**2. The LLM-as-Judge Agent (Silent Evaluator)**
Once the user has conversed enough, they trigger the Evaluation phase.
*   **Context Sharing:** Agent 2 (The Judge) does not talk to the user. Instead, it reads the entire chat transcript generated by Agent 1 and the User.
*   **Action:** Acting as a strict educational assessor, it analyzes the transcript against the RAG curriculum. It uses constrained JSON generation to output a strict schema identifying what the user understood, what their specific conceptual **gaps** are, and assigns a baseline mastery score.

**3. The Adaptive Quiz Master Agent (Targeted Assessor)**
To solidify learning, the user enters the quiz phase.
*   **Context Sharing:** Agent 3 takes the exact JSON `gaps` identified by Agent 2.
*   **Action:** It prompts the LLM to generate a dynamic, multiple-choice question designed specifically to test the user's weaknesses (the `gaps`). The difficulty of the question is chosen by an Item Response Theory model (Rasch/1PL): the band whose difficulty parameter is nearest the student's current ability estimate θ, and θ is updated after each answer with an Expected-A-Posteriori (Bayesian) step that scales with how surprising the answer was.
*   **Fast-Path Checking:** When the user answers, the backend instantly verifies correct answers. If wrong, it uses the LLM to generate a targeted pedagogical correction.
*   **Persistence:** The new IRT theta (mastery score) is asynchronously saved to Supabase, permanently updating the user's progress.

## Core AI Concepts

### 1. Socratic Tutor (Feynman Technique)
The AI never answers directly. It asks *you* to explain the concept, analyzes your response, and asks probing questions that guide you to the correct answer yourself. This mirrors how expert teachers operate.

### 2. Structured / Relational RAG (Why No Vector DB is Required)
Retrieval-Augmented Generation (RAG) is fundamentally about **fetching external authoritative context at query time and injecting it into the LLM prompt to prevent hallucination**. 

* **Vector DB RAG vs. Relational RAG**: Vector databases (like Pinecone or Chroma) excel at unstructured semantic similarity search across large PDF libraries. However, for structured educational syllabi, vector similarity search can be noisy or return incomplete chunks.
* **How NeoLearn implements RAG**: When a user selects a topic (e.g., *Quantum Superposition*), the backend retrieves the verified, structured curriculum record (`explanation`, `key_takeaway`, `core_concepts`) directly from Supabase by `topic_id`. This context is dynamically injected into **Layer 2** of the LangChain system prompt before any LLM inference occurs. This guarantees **100% deterministic precision** and zero hallucination.

### 3. LLM-as-Judge Evaluation
After the conversation, a second LLM call with a constrained JSON schema grades the dialogue transcript:
```json
{
  "score": 0.82,
  "understood": ["concept A", "concept B"],
  "gaps": ["concept C", "misconception about D"]
}
```

### 4. Adaptive Quiz Engine (IRT Model)
The `gaps` array from the Judge is fed directly into the quiz generator. Questions are calibrated using **Item Response Theory (IRT)** to target difficulty parameters at the exact concepts the student failed to grasp.

## Local Setup

### Prerequisites
- Node.js v18+
- Python 3.10+
- A [Supabase](https://supabase.com) project
- A [Groq](https://console.groq.com) API key

### 1. Backend

```bash
cd backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Create `backend/.env`:
```env
GROQ_API_KEY=your_groq_api_key
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_SERVICE_KEY=your_supabase_service_role_key
SUPABASE_JWT_SECRET=your_supabase_jwt_secret
```

Run:
```bash
uvicorn app.main:app --host 0.0.0.0 --port 8080 --reload
```
API docs available at `http://localhost:8080/docs`

### 2. Frontend

```bash
cd frontend
npm install
```

Create `frontend/.env`:
```env
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your_supabase_anon_key
VITE_API_URL=http://localhost:8080/api/v1
```

Run:
```bash
npm run dev -- --port 8081
```
Open `http://localhost:8081`

### 3. Docker (Backend only)

```bash
cd backend
docker-compose up --build
```
